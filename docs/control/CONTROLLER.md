# Monitra 总控契约

本目录是 Monitra 的项目控制面，只保存治理、审查和推进状态，不定义产品。

## 权威顺序

1. `docs/inspire.md` 是唯一产品愿景权威。
2. `docs/process-plan.md` 规定滚动推进方法，不增加产品事实。
3. 用户确认后的领域术语进入 `CONTEXT.md`，重要设计进入 `docs/adr/`。
4. 只有完成设计并获确认的当前范围，才能进入 `.scratch/<frontier>/spec.md` 和对应 issues。
5. 代码、任务答复、测试和演示都是证据，不能反向替产品或架构作决定。

若文档、任务答复、代码或运行证据互相冲突，总控停止晋级，在 `CURRENT.md` 记录差异并等待澄清。

## 总控边界

总控负责：

- 从仓库事实恢复当前前沿、Gate、等待事项和下一步；
- 维护 `CURRENT.md`、`TASK_INDEX.md`、`PROGRESS_LOG.md` 和 `../product/CAPABILITY_COVERAGE.md`；
- 审查用户指定的独立任务，并把结论与证据持久化；
- 当前前沿验收后重新观察全景，提出一至三个候选下一前沿；
- 为用户生成带明确 Skill、权威、范围、停止条件和证据要求的可复制 Prompt。

总控不负责：

- 普通业务设计或生产代码实现；
- 直接修复独立任务的问题；
- 替用户确认产品、领域或技术决策；
- 因测试绿色或任务自报完成而自动晋级；
- 自动继续已结束的独立任务。

## 每次开始或恢复

按下面顺序从磁盘重建状态，不依赖会话记忆：

1. 完整读取 `AGENTS.md`、`docs/inspire.md`、`docs/process-plan.md`。
2. 若存在，完整读取 `CONTEXT.md`、相关 `docs/adr/`、当前 `.scratch/` Spec/Ticket 和本控制目录。
3. 检查当前工作目录、分支、HEAD、工作区改动、代码入口、测试入口和运行方式。
4. 若仓库有 `.codegraph/`，理解代码时先使用 CodeGraph。
5. 对照 `CURRENT.md` 和 `CAPABILITY_COVERAGE.md`；过期状态按当前事实修正，并在 `PROGRESS_LOG.md` 留下接受后的变更事件。
6. 若发现冲突，停止晋级并明确等待谁决定什么。

恢复后必须能回答：当前前沿是什么、处于哪个 Gate、进入下一 Gate 还缺什么、哪些事项等待用户决定。

## 独立任务审查

用户提供任务 ID 后：

1. 完整读取该任务的原授权和最终答复，必要时分页，不用关键词、正则或自报状态判断成功。
2. 对照当前 `inspire.md`、`process-plan.md`、Spec/Ticket、领域/ADR 和本地真实代码。
3. 核查用户结果、生产代码、数据、权限、追溯、失败恢复和运行证据，以及范围漂移、未经确认的决定、重复模型和孤立对象。
4. 固定结论只能是：`接受`、`需要修正`、`证据不足`、`需要用户决定`。
5. 只有结论为 `接受`，才能更新正式进度和能力状态；设计、Spec、代码和运行验收分别记录，不互相替代。
6. 若需要后续动作，生成新 Prompt，不直接修复、不自动继续原任务。

## Gate

当前前沿依次通过以下 Gate；不满足前一项不得晋级：

1. **选择**：用户确认唯一当前前沿。
2. **设计**：阻塞实现的产品、领域和技术决定逐个确认并进入权威文档。
3. **Spec**：当前范围、明确不做和验收接缝获用户确认。
4. **Tickets**：只拆当前前沿，依赖关系和粒度获确认。
5. **实现**：每次只实现一张已就绪 Ticket。
6. **任务审查**：按原授权和当前事实审查独立任务。
7. **前沿验收**：用户结果、代码、数据、权限、追溯、失败恢复和运行证据闭环。
8. **全景回写**：接受后更新能力覆盖，再推荐下一前沿并等待确认。

实现中暴露新的产品或技术决定时，立即退回设计 Gate。

## 下一步 Prompt 格式

每条导航 Prompt 必须写明：

- 应调用的 Skill；
- 唯一目标；
- 必读权威与当前事实；
- 允许修改范围；
- 明确不做；
- 遇到何种决定或冲突必须停止；
- 必须返回的代码、测试、运行或决策证据。

推荐顺序为：`$grill-with-docs` → `$to-spec` → 用户确认 → `$to-tickets` → 每次 `$implement` 一张 Ticket → `$code-review`/运行证据验收。

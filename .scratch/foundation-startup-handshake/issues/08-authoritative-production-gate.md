# 08 — 权威门禁拒绝被测试依赖污染的生产产物

Type: evidence
Status: ready-for-agent
Blocked by: 06 — Playwright 验证浏览器启动成功与明确失败; 07 — 生产栈证明数据库首次失败及运行期自动恢复

**What to build:** 建立当前前沿唯一完整质量门禁，使本地和 CI 能用一个命令重复取得构建、契约、浏览器、数据库生命周期和生产纯净性证据，并拒绝含测试依赖的生产产物。

## Acceptance criteria

- [ ] `task check` 串联当前前沿全部必要门禁，并正确传播任意子门禁的非零退出码。
- [ ] CI 调用与本地相同的 `task check`，不维护第二套验收定义。
- [ ] 生产镜像不包含 Playwright、浏览器二进制、E2E源码、测试控制或开发服务器。
- [ ] 生产产物检查器能够拒绝含禁止内容的独立测试夹具。
- [ ] OpenAPI生成结果可重复，未同步生成物会使门禁失败。

## 它让系统向前移动什么

当前前沿获得一个稳定、可重复、可用于交接的完整验收入口，而不是依靠多条未关联的人工命令判断完成。

## 当前事实和调用链

前序 Ticket 分别建立代码、生产栈和验收入口，但尚未形成一个权威根命令，也未自动证明生产产物不受 E2E和开发依赖污染。

本 Ticket 建立：

```text
task check
→ Go测试与契约验证
→ TypeScript检查与Web测试
→ 生产镜像构建
→ Playwright生产栈验收
→ 数据库生命周期验收
→ 生产镜像内容检查
→ 汇总成功或非零失败
```

## 唯一主要结果

`task check` 成为当前前沿唯一权威门禁，并拒绝包含 E2E或开发依赖的生产产物。

## 输入和前置状态

- Ticket 06、07 的全部测试入口；
- 固定版本的 Go、Node.js、pnpm、Task和生成器；
- 最终生产镜像；
- 明确的生产镜像允许和禁止内容规则。

## 业务规则或待决问题

- 任意子门禁失败时整体必须非零退出。
- Playwright、浏览器、测试源码和测试控制不得进入生产镜像。
- 生成代码必须可重复；生成后存在未同步差异即失败。
- 生产验收仍以真实运行证据为准，不能把单个绿色测试等同于全部生产就绪。

## 成功后的状态变化

当前前沿的构建、契约、浏览器、数据库恢复和生产纯净性证据可由一个根命令重复取得。

## 失败或拒绝行为

使用独立测试夹具构造一个含 Playwright、E2E源码或其他禁止内容的伪生产文件系统或镜像清单。生产产物检查器必须明确拒绝它。

## 预计修改范围

- 根权威 Task 门禁；
- 生产镜像内容检查器及测试夹具；
- 生成代码一致性检查；
- CI入口；
- 当前前沿验收说明。

## 自动测试

1. 合法生产镜像通过纯净性检查。
2. 含测试依赖的夹具被检查器拒绝。
3. `task check` 串联全部当前前沿门禁并正确传播失败退出码。

## 运行演示

在干净环境运行一次 `task check`，展示各子门禁、生产镜像检查和最终成功结果。

## 明确不做

- 后续前沿测试；
- Release Bundle、签名、SBOM或漏洞扫描；
- 正式发布流水线；
- 以绿色门禁替代人工查看真实运行证据。

## 完成证据

- 完整 `task check` 输出；
- 生产镜像文件与依赖清单；
- 污染夹具被拒绝的测试；
- CI 调用同一命令的配置。
